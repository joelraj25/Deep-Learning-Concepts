Unit at a glance

The unit title comes from the first topic. A linear autoencoder learns a flat subspace (like PCA), while a non-linear autoencoder learns a curved surface, or manifold, on which real data lies. Convolutional networks then become the standard way to learn image features; four landmark architectures show how they grew deeper and more efficient, and three training tools make deep ConvNets trainable.

Topic 1 of 8 · Linear and manifolds

Autoencoders and Manifolds

1One-line definition

An autoencoder is a neural network trained to reproduce its input at its output through a narrow hidden layer (the bottleneck), so the encoder must learn a compact code that captures the data's structure; a linear autoencoder learns the same subspace as PCA, while a non-linear one learns a curved manifold.

2Diagram to draw

3Interactive demo: linear (PCA) vs non-linear autoencoder on a curved manifold

4Step-by-step explanation

In simple words

  1. Ask a network to copy its input, but force the message through a very small middle layer.
  2. To succeed it must keep only the important information and throw away noise: compression.
  3. The encoder squeezes; the decoder rebuilds. No labels are needed, the input is its own target.
  4. Real data such as face photos uses only a tiny part of all possible pixel patterns. That part is a smooth, curved surface: a manifold.
  5. The code z is like coordinates on that surface (pose, lighting, smile).

Technical version

  1. Undercomplete AE: code dimension d < input dimension; minimise \(L(x,g(f(x)))\).
  2. Linear AE ≡ PCA: with linear f and g and squared error, the optimal code spans the same subspace as the top d principal components.
  3. Manifold hypothesis: high-dimensional real data concentrates near a low-dimensional manifold; a non-linear AE learns a chart (coordinates) of it.
  4. Regularized AEs: sparse (L1 penalty on the code), denoising (reconstruct x from corrupted x̃), contractive (penalise \(\lVert\partial f/\partial x\rVert_F^2\)).
  5. Variational AE: encoder outputs a distribution; a KL term makes the code space smooth, so the decoder can generate new samples.
  6. Convolutional AE: encoder of conv + pooling, decoder of transposed convs / up-sampling; used for images (denoising, anomaly detection, pre-training CNN layers).

5Key formulas

\[z=f(x)=\sigma(W_ex+b_e)\qquad\qquad \hat x=g(z)=\sigma(W_dz+b_d)\qquad\qquad L=\frac1N\sum_{i=1}^{N}\lVert x_i-\hat x_i\rVert^2\] \[\textbf{Sparse:}\ \ L+\lambda\sum_j|z_j|\qquad\textbf{Denoising:}\ \ L=\lVert x-g(f(\tilde x))\rVert^2,\ \tilde x=x+\text{noise}\qquad\textbf{Contractive:}\ \ L+\lambda\Bigl\lVert\frac{\partial f(x)}{\partial x}\Bigr\rVert_F^2\] \[\textbf{VAE:}\quad L=\mathbb E_{q(z\mid x)}\bigl[-\log p(x\mid z)\bigr]+\text{KL}\bigl(q(z\mid x)\,\Vert\,\mathcal N(0,I)\bigr)\]
SymbolMeaning
\(x,\ \hat x\)Input and reconstruction.
\(z\)Code (latent representation) in the bottleneck.
\(f,\ g\)Encoder and decoder functions.
\(W_e,W_d\)Encoder and decoder weights (tied AEs use \(W_d=W_e^\top\)).
\(\tilde x\)Corrupted input for the denoising AE.
\(\lambda\)Strength of the regularization term.

6Worked example

An MNIST autoencoder 784 → 128 → 32 → 128 → 784 (fully connected). Count its parameters and its compression ratio. Then compute the reconstruction MSE for \(x=(1,\ 0,\ 0.5)\) and \(\hat x=(0.8,\ 0.1,\ 0.6)\).

  1. 784 → 128: 784 × 128 + 128 = 100,480.
  2. 128 → 32: 128 × 32 + 32 = 4,128. 32 → 128: 32 × 128 + 128 = 4,224.
  3. 128 → 784: 128 × 784 + 784 = 101,136. Total = 209,968 parameters.
  4. Compression: 784/32 = 24.5 times fewer numbers in the code.
  5. Errors: 0.2² = 0.04, (−0.1)² = 0.01, (−0.1)² = 0.01. MSE = 0.06/3 = 0.02.

Answer: 209,968 parameters; 24.5× compression; reconstruction MSE = 0.02.

7Advantages, disadvantages, applications

Advantages

  • Unsupervised: no labels needed.
  • Learns non-linear features, unlike PCA.
  • The code is a compact feature for other tasks.

Disadvantages

  • An overcomplete AE with no regularization can just copy the input.
  • Reconstructions are often blurry.
  • The code is learned for reconstruction, not necessarily for classification.

Applications

  • Dimensionality reduction and visualisation.
  • Image denoising.
  • Anomaly detection (high reconstruction error = unusual).
  • Pre-training, image compression, generation (VAE).

9Exam corner

2 marksWhat is an autoencoder?

A feed-forward network trained without labels to reconstruct its input. An encoder maps the input to a smaller code z = f(x), and a decoder maps it back, x̂ = g(z), minimising the reconstruction error ‖x − x̂‖².

2 marksState the manifold hypothesis.

Real high-dimensional data, such as natural images, lies on or near a low-dimensional manifold embedded in the input space, so a few latent coordinates are enough to describe it.

2 marksHow is a linear autoencoder related to PCA?

An autoencoder with linear encoder and decoder trained with squared error learns a code that spans the same subspace as the top principal components, so it performs PCA (up to a rotation of the code).

Topic 2 of 8 · ConvNets

Introduction to ConvNets

1One-line definition

A ConvNet (convolutional neural network) is a deep network for images built from a repeating pattern of convolution → ReLU → pooling layers, which learn local, shared filters and progressively shrink the spatial size, followed by fully connected layers that classify.

2Diagram to draw: the pipeline with sizes

3Interactive demo: output-size and parameter calculator

4Step-by-step explanation

In simple words

  1. Convolution: small filters slide over the image and light up where they find a pattern (edge, colour blob).
  2. ReLU: keeps positive responses, sets negatives to 0.
  3. Pooling: shrinks each map, keeping the strongest response in each 2×2 patch.
  4. Repeat: later layers find bigger patterns made from earlier ones.
  5. Flatten + fully connected: combine all features and output class scores; softmax turns them into probabilities.

Technical version

  1. Input volume W × H × C; a conv layer has K filters of size F × F × C, stride S, zero padding P.
  2. Local connectivity (each output sees an F × F patch) and parameter sharing (same filter everywhere) give far fewer weights than a fully connected layer and translation equivariance.
  3. Receptive field grows with depth: two stacked 3×3 convs see 5×5, three see 7×7.
  4. Pooling (max or average) has no parameters; it adds small translation invariance. Modern nets often use stride-2 convs or global average pooling instead.
  5. Training: softmax cross-entropy, backprop through conv (the gradient of a convolution is another convolution), SGD with momentum.

5Key formulas

\[O=\frac{W-F+2P}{S}+1\qquad\qquad \text{Output volume}=O\times O\times K\] \[\textbf{Parameters}=(F\cdot F\cdot C_{\text{in}}+1)\cdot K\qquad\qquad \textbf{Multiply-adds}=O\cdot O\cdot K\cdot F\cdot F\cdot C_{\text{in}}\] \[\textbf{Same padding (S = 1):}\ \ P=\frac{F-1}{2}\qquad\qquad \textbf{Receptive field of n stacked 3×3 convs}=2n+1\]
SymbolMeaning
\(W\)Input width (and height, for square inputs).
\(F\)Filter (kernel) size.
\(P\)Zero padding on each side.
\(S\)Stride.
\(K\)Number of filters = output channels.
\(C_{\text{in}}\)Input channels (depth of each filter).

6Worked example

Trace a 32×32×3 image through: conv 5×5, 6 filters, P = 0, S = 1 → ReLU → max pool 2×2, S = 2 → conv 5×5, 16 filters → ReLU → max pool 2×2 → FC 120. Then check AlexNet's first layer: 227×227×3 input, 96 filters of 11×11, S = 4, P = 0.

  1. Conv 1: (32 − 5 + 0)/1 + 1 = 28 → 28×28×6. Parameters (5·5·3 + 1)·6 = 456.
  2. Pool 1: (28 − 2)/2 + 1 = 14 → 14×14×6 (no parameters).
  3. Conv 2: (14 − 5)/1 + 1 = 10 → 10×10×16. Parameters (5·5·6 + 1)·16 = 2,416.
  4. Pool 2: (10 − 2)/2 + 1 = 5 → 5×5×16 = 400 values after flattening.
  5. FC 120: 400 × 120 + 120 = 48,120 parameters, far more than both conv layers together.
  6. AlexNet conv 1: (227 − 11)/4 + 1 = 55 → 55×55×96; parameters (11·11·3 + 1)·96 = 34,944.

Answer: 28×28×6 → 14×14×6 → 10×10×16 → 5×5×16 → 400 → 120; AlexNet conv 1 gives 55×55×96 with 34,944 parameters.

7Advantages, disadvantages, applications

Advantages

  • Few parameters thanks to weight sharing.
  • Learns a hierarchy of features automatically.
  • Translation equivariant; pooling adds invariance.

Disadvantages

  • Needs lots of labelled data and GPU time.
  • Not rotation or scale invariant by design.
  • Many design choices (depth, filters, stride).

Applications

  • Image classification, face recognition.
  • Backbone for detection and segmentation.
  • Medical imaging, OCR, video analysis.

9Exam corner

2 marksWrite the formula for the output size of a convolution layer.

O = (W − F + 2P)/S + 1, where W is the input size, F the filter size, P the padding and S the stride. The output depth equals the number of filters K.

2 marksWhat is parameter sharing?

The same filter weights are used at every spatial position of the input. A feature detector useful in one place is useful everywhere, and the number of weights becomes independent of image size.

2 marksWhat is the receptive field of a neuron?

The region of the input image that can affect that neuron. It grows with depth; for example, two stacked 3×3 conv layers give each output a 5×5 receptive field.

AlexNet and VGG

1One-line definition

AlexNet (2012) is an 8-layer CNN (5 conv + 3 fully connected) trained on GPUs with ReLU and dropout that won ImageNet 2012; VGG (2014) showed that depth matters by stacking 16–19 layers using only 3×3 convolutions and 2×2 max pooling.

2Diagram to draw

3Interactive demo: why VGG stacks 3×3 filters

4Step-by-step explanation

AlexNet (Krizhevsky, Sutskever, Hinton, 2012)

  1. Input 227×227×3; conv 1 has 96 filters of 11×11, stride 4 → 55×55×96.
  2. Then conv 5×5 (256), three conv 3×3 (384, 384, 256), with overlapping 3×3 stride-2 max pooling.
  3. Three FC layers: 4096, 4096, 1000 (softmax). About 60 M parameters, mostly in the FC layers.
  4. ReLU instead of tanh: trained about 6× faster.
  5. Dropout 0.5 in the FC layers; data augmentation (random crops, flips, colour changes).
  6. Trained on two GTX 580 GPUs (model split across them); also used local response normalization (LRN), later abandoned.

VGG (Simonyan and Zisserman, 2014)

  1. Question asked: what if we just go deeper with a simple, uniform design?
  2. All convs are 3×3, stride 1, padding 1 (size preserved); all pools are 2×2 stride 2 (size halved).
  3. Channels double after each pool: 64 → 128 → 256 → 512 → 512.
  4. VGG-16: 13 conv + 3 FC; VGG-19: 16 conv + 3 FC. About 138 M and 144 M parameters.
  5. Stacked 3×3 filters give large receptive fields with fewer weights and more non-linearity.
  6. Simple and very popular as a feature extractor (transfer learning, style transfer), but heavy: about 15.5 billion multiply-adds per 224×224 image.

5Key formulas

\[\textbf{AlexNet conv 1:}\quad \frac{227-11+0}{4}+1=55\ \Rightarrow\ 55\times55\times96\] \[\textbf{Receptive field of n stacked 3×3 convs:}\quad 2n+1\qquad\qquad \textbf{Weights:}\ \ n\cdot(3^2C^2)\ \text{vs}\ (2n+1)^2C^2\] \[\textbf{ReLU:}\ f(x)=\max(0,x)\qquad\qquad \textbf{Dropout:}\ \tilde h=r\odot h,\ r\sim\text{Bernoulli}(0.5)\]
SymbolMeaning
\(n\)Number of stacked 3×3 conv layers.
\(C\)Number of channels in and out of each layer (biases ignored).
\(r\)Random dropout mask.

6Worked example

(a) Compare weights of three 3×3 conv layers and one 7×7 layer with C = 256 channels. (b) Count VGG-16's first FC layer, which takes the 7×7×512 output of the last pool. (c) AlexNet conv 1 output and parameters.

  1. (a) Three 3×3: 3 × 9 × 256² = 27 × 65,536 = 1,769,472. One 7×7: 49 × 65,536 = 3,211,264.
  2. Ratio 27/49 = 0.55, so the stack uses 45% fewer weights for the same 7×7 receptive field.
  3. (b) 7 × 7 × 512 × 4096 + 4096 = 102,764,544: about 103 M of VGG-16's 138 M parameters sit in this one layer.
  4. (c) (227 − 11)/4 + 1 = 55 → 55×55×96; parameters (11·11·3 + 1) × 96 = 34,944.

Answer: 1.77 M vs 3.21 M weights; first FC layer of VGG-16 ≈ 102.8 M parameters; AlexNet conv 1 = 55×55×96 with 34,944 parameters.

7Advantages, disadvantages, applications

Advantages

  • AlexNet: proved deep CNNs + GPUs work; introduced practical ReLU and dropout.
  • VGG: very simple, uniform design; excellent transferable features.

Disadvantages

  • AlexNet: large early filters, LRN, many FC parameters.
  • VGG: 138 M parameters (over 500 MB), slow, memory hungry.
  • Both: plain stacking stops helping beyond about 20 layers.

Applications

  • Image classification baselines.
  • Feature extractor for detection (Fast R-CNN used VGG-16).
  • Neural style transfer and perceptual losses (VGG).

9Exam corner

2 marksList the key innovations of AlexNet.

ReLU activations, dropout in the fully connected layers, data augmentation, overlapping max pooling, and training on two GPUs; it won ILSVRC 2012 with 15.3% top-5 error.

2 marksWhy does VGG use 3×3 filters?

Stacked 3×3 layers achieve the same receptive field as larger filters (two give 5×5, three give 7×7) with fewer parameters and more ReLU non-linearities between them.

2 marksWhere are most of VGG-16's parameters?

In the fully connected layers; the first FC layer alone (7×7×512 → 4096) has about 103 million of the roughly 138 million parameters.

Inception (GoogLeNet)

1One-line definition

GoogLeNet (Szegedy et al., 2014) is a 22-layer CNN built from Inception modules, each running 1×1, 3×3 and 5×5 convolutions and 3×3 max pooling in parallel and concatenating the results, with 1×1 convolutions as bottlenecks to cut computation; it won ImageNet 2014 with only about 6.8 M parameters.

2Diagram to draw: the Inception module

3Interactive demo: how much the 1×1 bottleneck saves

4Step-by-step explanation

In simple words

  1. Which filter size is best: 1×1, 3×3 or 5×5? Objects appear at different sizes, so Inception uses all of them at once.
  2. Each branch looks at the same input with a different "zoom", and their outputs are stacked together.
  3. Big filters on many channels are very expensive, so a 1×1 conv first squeezes the channels down.
  4. The network stacks 9 such modules, ending with an average over each whole feature map instead of huge fully connected layers.

Technical version

  1. Naive module: parallel 1×1, 3×3, 5×5 convs and 3×3 max pool, concatenated; output channels pile up and computation explodes.
  2. Dimension reduction: 1×1 convs (with ReLU) before the 3×3 and 5×5 convs and after the pool. A 1×1 conv is a per-pixel fully connected layer across channels (the "network in network" idea, Lin et al., 2013).
  3. GoogLeNet: 22 weight layers, 9 Inception modules, about 6.8 M parameters (about 12× fewer than AlexNet).
  4. Global average pooling (7×7×1024 → 1024) replaces the large FC layers; then dropout 0.4 and one FC to 1000 classes.
  5. Auxiliary classifiers on intermediate layers add extra gradient signal during training (loss weight 0.3) and are removed at test time.
  6. Later versions: Inception-v2/v3 add batch norm and factorise 5×5 into two 3×3 (and n×n into 1×n + n×1); Inception-v4 and Inception-ResNet add residual connections.

5Key formulas

\[\textbf{Cost of a conv layer (multiply-adds)}=H\cdot W\cdot K\cdot F^2\cdot C_{\text{in}}\] \[\textbf{Naive 5×5:}\ \ H W\cdot K\cdot25\cdot C_{\text{in}}\qquad\qquad \textbf{With 1×1 reduce to }r:\ \ HW\cdot r\cdot C_{\text{in}}+HW\cdot K\cdot25\cdot r\] \[\textbf{Concatenated output channels}=K_{1\times1}+K_{3\times3}+K_{5\times5}+K_{\text{pool proj}}\]
SymbolMeaning
\(H,W\)Height and width of the feature map (kept the same inside a module).
\(C_{\text{in}}\)Input channels.
\(K\)Number of filters in a branch.
\(F\)Filter size.
\(r\)Channels after the 1×1 reduction.

6Worked example

Input 28×28×192. A 5×5 conv produces 32 channels ("same" padding). Compare its cost without and with a 1×1 conv that first reduces to 16 channels. Then find the output depth of Inception 3a (branches 64, 128, 32, 32).

  1. Naive: 28 × 28 × 32 × 5 × 5 × 192 = 120,422,400 ≈ 120.4 M multiply-adds.
  2. 1×1 reduce: 28 × 28 × 16 × 1 × 1 × 192 = 2,408,448 ≈ 2.4 M.
  3. Then 5×5: 28 × 28 × 32 × 5 × 5 × 16 = 10,035,200 ≈ 10.0 M.
  4. Total with bottleneck ≈ 12.4 M: about 9.7× cheaper.
  5. Inception 3a output depth: 64 + 128 + 32 + 32 = 256 channels, so 28×28×256.

Answer: 120.4 M vs 12.4 M multiply-adds (≈ 10× saving); module output 28×28×256.

7Advantages, disadvantages, applications

Advantages

  • Multi-scale features in every module.
  • Very few parameters (≈ 6.8 M) for its accuracy.
  • Efficient: 1×1 bottlenecks and global average pooling.

Disadvantages

  • Complex, hand-designed modules; many hyperparameters.
  • Harder to modify than VGG or ResNet.
  • Auxiliary classifiers complicate training.

Applications

  • Image classification on limited compute.
  • Backbone for detection.
  • Medical imaging (Inception-v3 is widely used for transfer learning).

9Exam corner

2 marksWhat is the role of 1×1 convolution in Inception?

It reduces the number of channels (dimension reduction) before expensive 3×3 and 5×5 convolutions, cutting computation and parameters, and adds an extra ReLU non-linearity.

2 marksWhat is global average pooling?

Each feature map is averaged over all its positions to a single number (e.g. 7×7×1024 → 1024). It replaces large fully connected layers, has no parameters, and reduces overfitting.

2 marksWhy does GoogLeNet use auxiliary classifiers?

Small classifiers attached to middle layers add extra loss terms during training, injecting gradient into the lower layers to fight vanishing gradients and to regularize. They are discarded at test time.

ResNet (Residual Networks)

1One-line definition

ResNet (He et al., 2015) is a very deep CNN made of residual blocks in which a shortcut (skip) connection adds the block's input to its output, y = F(x) + x, so each block only learns a residual F(x); this made 152-layer networks trainable and won ImageNet 2015.

2Diagram to draw: residual blocks

3Interactive demo: gradient flow in plain vs residual networks

4Step-by-step explanation

In simple words

  1. Surprise found by He et al.: a plain 56-layer CNN had higher training error than a 20-layer one. Not overfitting, just harder to optimise (the degradation problem).
  2. A deeper net should be at least as good: extra layers could just copy their input. But learning "copy" with conv layers is hard.
  3. Fix: give every block a free copy path (the shortcut) and let the layers learn only the change F(x) to add.
  4. If no change is needed, the layers can learn F(x) ≈ 0, which is easy.
  5. Gradients also travel backwards along the shortcuts, so even layer 1 of 152 keeps learning.

Technical version

  1. Residual learning: to represent H(x), learn F(x) = H(x) − x and output y = F(x, {W_i}) + x.
  2. Shortcuts: identity (no parameters) when shapes match; projection \(W_sx\) (1×1 conv) when they change.
  3. Backprop: \(\partial L/\partial x=\partial L/\partial y\,(1+\partial F/\partial x)\); the 1 term passes gradient straight through.
  4. Architecture: 7×7 conv stride 2, 3×3 max pool, then 4 stages of blocks (64, 128, 256, 512 channels for basic blocks; ×4 output for bottlenecks), global average pooling, FC 1000. Batch norm after every conv; He initialization.
  5. Depths: ResNet-18, 34 (basic blocks); 50, 101, 152 (bottleneck blocks). ResNet-152: 3.57% top-5 (ensemble), ILSVRC 2015 winner. A 1202-layer version was also trained on CIFAR-10.
  6. Influence: skip connections appear in DenseNet, ResNeXt, U-Net and every Transformer layer.

6Worked example

(a) Weights of a bottleneck block on 256 channels vs two plain 3×3 convs on 256 channels (biases ignored). (b) Gradient through 5 layers whose derivatives are each 0.1, plain vs residual. (c) A block with x = (1, 2) and F(x) = (0.2, −0.5): find y.

  2. Two 3×3 convs on 256 channels: 2 × 9 × 256 × 256 = 1,179,648, about 17× more.
  3. (b) Plain: 0.1⁵ = 0.00001, so the gradient almost vanishes. Residual: (1 + 0.1)⁵ = 1.611, so it survives.
  4. (c) y = F(x) + x = (0.2 + 1, −0.5 + 2) = (1.2, 1.5); then ReLU leaves it unchanged.

Advantages

  • Trains networks with 100+ layers.
  • Solves the degradation problem; eases vanishing gradients.
  • Identity shortcuts add no parameters.
  • Simple, modular, easy to scale.

Disadvantages

  • Very deep versions are slow at inference.
  • Many blocks contribute little (redundancy).
  • Projection shortcuts add parameters.

Applications

  • Default backbone for classification, detection (Faster R-CNN, Mask R-CNN) and segmentation.
  • Transfer learning (ResNet-50 is the standard pretrained model).
  • Residual idea used in Transformers.

Weight Initialization

1One-line definition

Weight initialization is the choice of starting values for a network's weights; good schemes such as Xavier (Glorot) and He draw random weights with a variance scaled by the number of inputs so that activations and gradients keep roughly the same spread from layer to layer.

2Diagram to draw

3Interactive demo: activation spread through 10 layers

4Step-by-step explanation

In simple words

  1. Training starts from the initial weights, so a bad start can stop training before it begins.
  2. All zeros: every neuron computes the same thing and gets the same update, so they stay twins forever (no symmetry breaking).
  3. Random but too small: each layer shrinks the signal, so deep layers see almost nothing.
  4. Random but too big: the signal grows or saturates the activation.
  5. Just right: scale the random weights by the number of inputs so the signal size stays constant.

Technical version

  1. For \(y=\sum_{i=1}^{n_{\text{in}}}w_ix_i\) with independent zero-mean terms, \(\text{Var}(y)=n_{\text{in}}\,\text{Var}(w)\,\text{Var}(x)\).
  2. Keeping \(\text{Var}(y)=\text{Var}(x)\) forward needs \(\text{Var}(w)=1/n_{\text{in}}\) (LeCun); backward needs \(1/n_{\text{out}}\).
  3. Xavier / Glorot (2010) compromises: \(\text{Var}(w)=2/(n_{\text{in}}+n_{\text{out}})\); derived for symmetric activations like tanh.
  4. He / Kaiming (2015): ReLU outputs zero for half the inputs, halving the variance, so use \(\text{Var}(w)=2/n_{\text{in}}\).
  5. For conv layers, \(n_{\text{in}}=F\cdot F\cdot C_{\text{in}}\). Biases are usually set to 0.
  6. Batch norm (Topic 7) and residual connections make networks less sensitive to initialization, but He init is still the default for ReLU ConvNets.

5Key formulas

\[\text{Var}(y)=n_{\text{in}}\,\text{Var}(w)\,\text{Var}(x)\] \[\textbf{Xavier normal:}\ \ w\sim\mathcal N\Bigl(0,\ \frac{2}{n_{\text{in}}+n_{\text{out}}}\Bigr)\qquad \textbf{Xavier uniform:}\ \ w\sim U\Bigl[-\sqrt{\tfrac{6}{n_{\text{in}}+n_{\text{out}}}},\ \sqrt{\tfrac{6}{n_{\text{in}}+n_{\text{out}}}}\Bigr]\] \[\textbf{He normal:}\ \ w\sim\mathcal N\Bigl(0,\ \frac{2}{n_{\text{in}}}\Bigr)\qquad\qquad \textbf{LeCun:}\ \ w\sim\mathcal N\Bigl(0,\ \frac{1}{n_{\text{in}}}\Bigr)\]
SymbolMeaning
\(n_{\text{in}}\)Fan-in: number of inputs to a unit (F·F·Cin for a conv layer).
\(n_{\text{out}}\)Fan-out: number of outputs (F·F·K for a conv layer).
\(\mathcal N(0,v)\)Normal distribution with mean 0 and variance v.
\(U[-a,a]\)Uniform distribution; its variance is a²/3.

6Worked example

A fully connected layer with 256 inputs and 256 outputs. Find the standard deviation for Xavier normal, He normal and the Xavier uniform limit. Then find He's σ for a 3×3 conv layer with 64 input channels.

  1. Xavier normal: Var = 2/(256 + 256) = 1/256, so σ = 1/16 = 0.0625.
  2. He normal: Var = 2/256 = 1/128, so σ = 0.0884.
  3. Xavier uniform: limit = √(6/512) = 0.1083; check variance = 0.1083²/3 = 0.0039 = 1/256.
  4. Conv layer: n_in = 3 × 3 × 64 = 576; He σ = √(2/576) = 0.0589.
  5. Check with σ = 0.0625 and Var(x) = 1: Var(y) = 256 × 0.0039 × 1 = 1.0, so the spread is preserved.

Answer: Xavier σ = 0.0625; He σ = 0.0884; Xavier uniform limit ±0.108; He σ for the conv layer = 0.0589.

7Advantages, disadvantages, applications

Good initialization gives

  • Faster, more reliable convergence.
  • No vanishing or exploding signals at the start.
  • Symmetry broken so units learn different features.

Limitations

  • Derivations assume independent inputs and specific activations.
  • Only fixes the start; training can still drift.
  • Very deep nets also need BN or residual connections.

Where used

  • He: ReLU ConvNets (ResNet, VGG retrained).
  • Xavier: tanh / sigmoid networks, many RNN layers.
  • Pretrained weights: transfer learning as initialization.

2 marksWhy should weights not be initialized to zero?

All neurons in a layer would compute the same output and receive the same gradient, so they would stay identical forever (the symmetry problem); the layer would behave like a single neuron.

2 marksState Xavier initialization.

2 marksWhy is He initialization preferred for ReLU?

ReLU sets about half its inputs to zero, halving the output variance. He initialization doubles the weight variance to 2/n_in to compensate, keeping the signal stable through many layers.

Batch Normalization in ConvNets

1One-line definition

Batch normalization (Ioffe and Szegedy, 2015) normalizes each layer's activations using the mini-batch mean and variance and then applies a learned scale γ and shift β; in a ConvNet the statistics are computed per channel, over all images in the batch and all spatial positions.

2Diagram to draw

3Interactive demo: which numbers are averaged?

4Step-by-step explanation

In simple words

  1. Each channel of a conv layer is one feature detector (say, "vertical edge").
  2. BN looks at that channel's values across every image in the batch and every pixel position, and rescales them to mean 0, spread 1.
  3. Then γ and β (one pair per channel) let the network pick its own scale and centre.
  4. At test time, saved running averages replace the batch statistics.
  5. Result: higher learning rates, faster training, less sensitivity to initialization.

Technical version

  1. For a tensor N × C × H × W: \(\mu_c=\frac{1}{NHW}\sum_{n,h,w}x_{n,c,h,w}\) and likewise \(\sigma_c^2\); one γ_c and β_c per channel.
  2. Per-channel (not per-pixel) statistics keep the convolution property: the same normalization applies at every location.
  3. Placed after conv and before ReLU; the conv bias is redundant.
  4. Inference: \(\mu_{\text{run}}\leftarrow m\mu_{\text{run}}+(1-m)\mu_c\); BN can then be folded into the conv weights for speed.
  5. First used at scale in Inception-v2 (BN-Inception), which reached the original GoogLeNet's accuracy in 14× fewer training steps; every ResNet conv is followed by BN.
  6. Small batches give noisy statistics; alternatives are group norm, layer norm and instance norm.

5Key formulas

\[\mu_c=\frac{1}{NHW}\sum_{n=1}^{N}\sum_{h=1}^{H}\sum_{w=1}^{W}x_{n,c,h,w}\qquad\qquad \sigma_c^2=\frac{1}{NHW}\sum_{n,h,w}\bigl(x_{n,c,h,w}-\mu_c\bigr)^2\] \[\hat x_{n,c,h,w}=\frac{x_{n,c,h,w}-\mu_c}{\sqrt{\sigma_c^2+\varepsilon}}\qquad\qquad y_{n,c,h,w}=\gamma_c\,\hat x_{n,c,h,w}+\beta_c\] \[\textbf{Learnable BN parameters per layer}=2C\qquad\qquad \textbf{Stored running statistics}=2C\]
SymbolMeaning
\(N,C,H,W\)Batch size, channels, height, width.
\(\mu_c,\ \sigma_c^2\)Mean and variance of channel c over the batch and positions.
\(\gamma_c,\ \beta_c\)Learned scale and shift for channel c.
\(\varepsilon\)Small constant for numerical safety.
\(m\)Momentum of the running average (e.g. 0.9).

6Worked example

Channel 1 of a batch of two images: image 1 has pixels (1, 3, 5, 7), image 2 has (2, 4, 6, 8). Compute μ, σ², and the normalized values of 1 and 8. Then count BN parameters for a layer with 64 channels.

  1. All 8 values pooled: μ = (1 + 3 + 5 + 7 + 2 + 4 + 6 + 8)/8 = 36/8 = 4.5.
  2. Squared deviations: 12.25, 2.25, 0.25, 6.25, 6.25, 0.25, 2.25, 12.25; sum = 42; σ² = 42/8 = 5.25; σ = 2.291.
  3. x̂ for 1: (1 − 4.5)/2.291 = −1.528. x̂ for 8: (8 − 4.5)/2.291 = +1.528.
  4. With γ = 1, β = 0 these are the outputs; the network can learn other γ, β.
  5. 64 channels: 2 × 64 = 128 learnable parameters, plus 128 running statistics.

Answer: μ = 4.5, σ² = 5.25; x̂ = −1.528 and +1.528; 128 learnable BN parameters.

7Advantages, disadvantages, applications

Advantages

  • Much higher learning rates; faster convergence.
  • Less sensitive to weight initialization.
  • Mild regularization; can reduce dropout use.
  • Makes 100+ layer ConvNets practical.

Disadvantages

  • Depends on batch size; poor with tiny batches.
  • Train and test behave differently.
  • Extra memory and computation in training.

Applications

  • Inception-v2/v3, ResNet, DenseNet.
  • GAN generators and discriminators (DCGAN).
  • Almost every modern image classifier.

Hyperparameter Optimization

1One-line definition

Hyperparameter optimization is the search for the settings that are chosen before training, not learned by it (learning rate, batch size, depth, dropout, weight decay), by training models with different settings and keeping the one with the best validation performance, using strategies such as grid search, random search or Bayesian optimization.

2Diagram to draw

3Interactive demo: grid search vs random search

4Step-by-step explanation

In simple words

  1. Weights are learned by training; hyperparameters are knobs you set before training starts.
  2. Split data into training, validation and test sets.
  3. Try some settings, train, check validation accuracy, and keep the best.
  4. Grid search tries every combination of a few values. Random search picks random combinations. Bayesian optimization uses past results to guess where to try next.
  5. Finally report the best model's accuracy on the untouched test set.

Technical version

  1. Objective: \(\lambda^*=\arg\max_\lambda\ \text{Acc}_{\text{val}}(\text{train}(\lambda))\); each evaluation is a full (or partial) training run, so it is very expensive.
  2. Grid search: cost grows as \(v^d\) (v values for each of d hyperparameters).
  3. Random search (Bergstra and Bengio, 2012): usually only a few hyperparameters matter; random sampling explores more distinct values of each.
  4. Search scales: sample learning rate and weight decay on a log scale, e.g. \(\eta=10^{u},\ u\sim U(-5,-1)\).
  5. Coarse-to-fine: a short wide search, then a narrow search around the best region.
  6. Smarter methods: Bayesian optimization (Gaussian-process surrogate + acquisition function), Hyperband / successive halving (stop bad runs early), population-based training, and k-fold cross-validation for small datasets.

5Key formulas

\[\lambda^*=\arg\max_{\lambda\in\Lambda}\ \text{Acc}_{\text{val}}\bigl(w^*(\lambda)\bigr)\qquad\text{where}\qquad w^*(\lambda)=\arg\min_w\ L_{\text{train}}(w;\lambda)\] \[\textbf{Grid cost}=\prod_{j=1}^{d}v_j\qquad\qquad \textbf{Log-uniform sampling:}\ \ \eta=10^{u},\ u\sim U(a,b)\] \[\textbf{Chance random search hits the top 5\% in n trials}=1-0.95^{\,n}\]
SymbolMeaning
\(\lambda,\ \Lambda\)A setting of hyperparameters and the search space.
\(w^*(\lambda)\)Weights learned by training with setting λ.
\(d,\ v_j\)Number of hyperparameters; values tried for hyperparameter j.
\(u\)Uniform random exponent for log-scale sampling.
\(n\)Number of random trials.

6Worked example

(a) A grid over 4 hyperparameters with 5 values each, 2 GPU-hours per run: total cost? (b) With 9 trials on 2 hyperparameters, how many distinct learning rates do grid and random search test? (c) How many random trials give a 95% chance of landing in the top 5% of the space? (d) Sample a learning rate with u = −2.6.

  1. (a) 5⁴ = 625 runs × 2 h = 1,250 GPU-hours (about 52 days on one GPU).
  2. (b) Grid 3 × 3: only 3 distinct learning rates. Random: 9 distinct learning rates.
  3. (c) Need 1 − 0.95ⁿ ≥ 0.95, so 0.95ⁿ ≤ 0.05, n ≥ ln 0.05 / ln 0.95 = 58.4, so n = 59 trials.
  4. (d) η = 10^(−2.6) = 0.00251.

Answer: 625 runs (1,250 GPU-hours); 3 vs 9 distinct learning rates; 59 random trials; η ≈ 0.0025.

7Advantages, disadvantages, applications

Grid search

  • + Simple, systematic, reproducible.
  • + Easy to run in parallel.
  • − Exponential cost in the number of hyperparameters.
  • − Wastes trials on unimportant parameters.

Random search

  • + More distinct values of important parameters.
  • + Budget can be any size; easy to stop and extend.
  • − No guarantee of covering a region.
  • − Does not learn from earlier trials.

Bayesian optimization

  • + Uses past results; fewer trials needed.
  • − Sequential and more complex.
  • Used in AutoML tools (Optuna, Hyperopt, Google Vizier).

9Exam corner

2 marksDifferentiate parameters and hyperparameters.

Parameters (weights, biases) are learned from data during training. Hyperparameters (learning rate, batch size, number of layers, dropout) are set before training and chosen using validation performance.

2 marksWhy is random search often better than grid search?

Usually only a few hyperparameters matter. With the same number of trials, random search tests many more distinct values of each important hyperparameter, while grid search repeats the same few values.

Its effect depends on its order of magnitude (0.001 vs 0.01 matters more than 0.010 vs 0.011), so sampling the exponent uniformly spreads trials evenly across magnitudes.
